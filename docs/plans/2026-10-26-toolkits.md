**Goal:** Skills reuse shared tools from a toolkit instead of carrying copies, every tool declares
what it touches, and a run leaves exactly the requested outputs in the user's folder.

---

## What it does

- **Toolkits.** `toolkits/<name>/` has the same shape as a skill (`tools.yaml` + `python/` +
  `native/`), with no prompt or corpus. A skill declares `toolkits: [fs]` and its plans use the
  toolkit's tools through the host; its own `tools.yaml` no longer copies them. Toolkit tools are
  internal unless the skill lists them under `expose:`. The first toolkit is `fs` (input
  resolution, folder listing, moving results into place); `net` follows in the URL-inputs plan.
- **One contract per tool.** Every tool is defined once in YAML and once as a class, matched by
  name, strictly one to one; a skill's handlers list, import list and duplicated manifest keys are
  gone. `resolve_inputs` exists once, in the `fs` toolkit.
- **The run scratch.** Chain intermediates, previews and partial files go to a per-run scratch
  folder (`<OS temp>/knaif/run-<id>/`). A result is written there, checked, and moved into the
  user's folder, so an interrupted or failed chain leaves nothing half-written behind.
- **Declared effects.** Every skill and toolkit tool declares `effects:` (`fs.read`, `fs.write`,
  `net`, `exec:<program>`, or `[]`); a bundle with an undeclared tool does not load. A handler runs
  a program only through `ctx.exec` and writes only through the `fs` toolkit, both refused for an
  undeclared effect. Python enforces the declarations at run time, native validates them at load,
  and a lint keeps direct I/O out of tool modules (18 reasoned exceptions).

## Bar and evidence

Fixed before measuring, all met on both runtimes:

| Bar | Result |
|---|---|
| Nothing the model sees changes | prompt, retrieval and tool list byte-identical for all 1,025 corpus utterances; L1 at 100% |
| Behaviour preserved | both skills' regression gates pass on the executing verifier after fixture regeneration |
| L2 deterministic parity | 100%, with new contract cases for scratch routing and effects |
| Exact files | a check that the output folder holds exactly the expected files fails before the scratch and passes after, on every chain and preview row, both runtimes |
| Duplication | every generic helper has one home in `fs`, or a written reason to stay |

## What a skill author sees

`docs/TOOL_SCHEMA.md` documents the toolkit layout, `expose:`, the effects vocabulary, `ctx.exec`,
`ctx.call_tool` and the run scratch. The site's authoring page (*steps and intents*) follows it.

## Out of scope

Native run-time enforcement of effects (native validates at load; run-time enforcement waits for
the native handler context). The stale `io` skill moves onto `fs` when it is rebuilt.
