## Decisions

- 2026-09-30 — macOS ships in 1.3.0, not a 1.2.x patch: a new platform is a minor
  ([release-workflow](2026-09-30-release-workflow.md) decision 5).
- 2026-09-30 — the earlier "knaif 1.3" scope plan becomes the adapters/superskill feature plan;
  this file is the release index.
- 2026-09-30 — macOS signing and notarization ship with macOS; the owner's certificate steps
  are [macos-signing-certificates](2026-09-30-macos-signing-certificates.md). Windows
  signing is tracked in `code-signing` and is proposed for 1.2.1.
- 2026-10-05 — per-skill adapters and the superskill leave 1.3.0 (probably); they are assigned to
  a version not yet chosen.
- 2026-10-05 — daemon mode and "Yes as the default, except when overwriting" are in 1.3.0; every
  other item carried from 1.2.1 joins 1.3.0 too.
- 2026-10-05 — **overwrite policy:** ordinary steps ask `Proceed? [Y/n]`; a step whose output
  already exists asks separately with **No** as the default (Enter keeps the file), and the default
  `--yes` does not approve it — replacing needs its own explicit flag. ffmpeg stops passing a blanket
  `-y`.
- 2026-10-05 — **daemon mode is opt-in and started explicitly** (`start`/`stop`/`status`; exact
  names in D0), or from a run with `knaif run … --daemon`; `run` uses a running daemon and otherwise
  loads the model itself; idle shutdown.
- 2026-10-05 — non-macOS 1.3.0 work goes on one working branch, `feat/1.3.0`, cut from
  `release/1.3.0`, merged back by one PR. macOS keeps `feat/macos-support`.
- 2026-10-05 — added to scope: the download page wording move (chosen 2026-10-03, TODO.md) and the
  VS Code prompt-line bug shipped open in 1.2.1.
- 2026-10-06 — **the as-built prompting replaces the 2026-10-05 overwrite decision** (owner,
  confirmed after the build): `run` acts without asking; `--confirm` opts in to `Proceed? [Y/n]`
  (Enter approves). Replacing an existing file always asks `Replace <file>? [y/N]` (Enter keeps it),
  `--yes` never approves that, `--overwrite` does, and without a terminal the step stops.
- 2026-10-06 — **ffmpeg keeps `-y`** (owner): the rendered commands are a parity contract and the
  eval baselines' command text, so knaif's replace gate runs before ffmpeg instead of ffmpeg refusing.
- 2026-10-02 — 1.2.1 shipped (Windows signing included) and `main` was merged in; its deferred
  items are listed under *Carried from 1.2.1*.

## Carried from 1.2.1

Moved here by owner decision during 1.2.1 (its index, *Deferred*). On 2026-10-05 all of them were
brought into 1.3.0; each still needs a plan before it is built.

- **Yes as the prompt default, and `--yes` as the default** with an opt-in flag to ask first
  (TODO.md). Decided 2026-10-05: Yes is the default **except when the step would overwrite**,
  which still asks.
- **Overwrite policy for outputs:** ffmpeg replaces an existing output without asking (every
  command carries `-y`), and documents does the same for an explicit `output`; ask, or suffix as
  documents' auto names do (TODO.md).
- **Daemon mode** — keep the model loaded between runs and reuse the processed prompt prefix
  ([daemon-mode](2026-10-01-daemon-mode.md), Draft; in 1.3.0 per the Scope table).
- The clarify message that names an internal argument (parity-contract wording). **Done** 2026-10-06:
  `I can't adjust volume that way — that isn't supported. Could you rephrase?`, both runtimes and
  `contracts/parity/arg_gate_cases.json`.
- **Out of 1.3.0 (owner, 2026-10-06):** "the second frame" planned as the first; `ffmpeg_138#0` ("…and then reduce its bitrate" asks
  instead of planning), now the same on both runtimes, so a model/prompt item.
- The Python runtime finding supporting tools on PATH only; tool version detection. The lookup is
  **done** 2026-10-06 (documents: override variable, `PATH`, declared folders, as native). Version
  detection: **not a runtime check** (owner, 2026-10-06) — each skill's SPEC lists the versions knaif
  is tested with and says older ones may not work. Done 2026-10-06.
- **Out of 1.3.0 (owner, 2026-10-06):** the ARM64 Windows warn-and-allow check in the installer.
