**Goal:** Fix bugs found in 1.2.0 without changing behavior on the platforms it shipped for.

## Current state

Scope chosen 2026-10-01: native bug fixes, a readable terminal view for `knaif run`, and Windows
signing. The fixes and the terminal view are implemented on `fix/1.2.1` and await the owner's manual
test; signing waits on the Azure certificate. Cut from `main` at the commit that merged this index: since
`v1.2.0`, `main` gained only docs, eval records, CI, the plan lint and the site's download data,
none of which ships in an artifact.

## Exit gates

- The patch lane's gates in [RELEASE.md](../RELEASE.md) (*Branches and release lanes*): `just check`,
  the affected skill's L4 sampled, clean room, upgrade path.
- The patch rule: no new or retrained model, no prompt wording, no `tools.yaml` / contract change,
  no new CLI flag, no behavior change on a shipped platform. A fix that needs one moves to 1.3.0.

## Decisions

- 2026-09-30 — cut from `main` rather than `v1.2.0` (see *Current state*).
- 2026-09-30 — Windows installer signing is proposed for this patch (owner issues the Azure
  certificate); it qualifies only if the patch gates pass with a signed installer.
- 2026-10-01 — the confirmation changes (prompt defaulting to Yes; `--yes` as the default with a
  flag to ask instead) move to 1.3.0. They add a flag and change behavior, which the patch rule
  forbids.
- 2026-10-01 — the terminal redesign is in the patch because it is a display change. It turns on
  only when stdout and stderr are terminals and adds no flag, and piped output keeps every line the
  eval lane and scripts read.
- 2026-10-01 — the ffmpeg command stays visible in the new view. Only llama.cpp's own output is
  hidden, and `--verbose` shows everything. The owner decides on the terminal logo after seeing it.
- 2026-10-01 — the terminal logo ships as plain-ASCII `kn[AI]f` on bare `knaif` and `--help`
  (block-character versions rejected; details in cli-terminal-output T6).
- 2026-10-01 — after the owner's test round 2: B5 is fixed on both runtimes (a backslash password
  kept the user's spelling on neither), the Python batch failure is fixed (B9), and B7 is done. The
  patch therefore touches the Python runtime too, for those two bug fixes only; no prompt, model or
  contract changes.
- 2026-10-01 — all 1.2.1 work happens on one branch, `fix/1.2.1`, and goes into `release/1.2.1` in
  one PR at the end (the `release-branches` ruleset requires a PR and allows no bypass).

## Deferred

- To 1.3.0: Yes as the prompt default and `--yes` as the default with an opt-in confirm flag
  (the TODO.md item covers both); the clarify message that names an internal argument
  (parity-contract wording); "the second frame" planned as the first; Python finding supporting
  tools on PATH only; tool version detection. Add them to the 1.3.0 index on `release/1.3.0`.
- To 1.3.0, from the owner's test round 1 (2026-10-01): a **daemon mode** that keeps the model in
  VRAM between runs (new behavior and surface; measured 2026-10-01: model load is ~1.05 s of a 2.0 s
  CUDA run, while on CPU prompt processing dominates, 6.4 of 11 s, which prefix reuse addresses;
  [daemon-mode](2026-10-01-daemon-mode.md), proposed for 1.3.0); and an **overwrite policy** — ffmpeg replaces an existing output without asking
  (every command carries `-y`, an auto-generated name included), and documents does the same for an
  explicit `output`, while its auto-generated names already get `-1`. The terminal view now warns; the
  decision on asking or auto-suffixing is open, and it bears on the Yes-default item: that item's
  premise ("nothing can overwrite an existing file") holds for documents' auto names only.
- Not a code fix: `knaif-qwen3-1.7b-v2` slice gaps (needs a model).
- To 1.3.0 (owner, 2026-10-01): the ARM64 Windows warn-and-allow check in the installer
  (untestable here without the hardware), and `ffmpeg_138#0` ("…and then reduce its bitrate" asks
  instead of planning). The latter is now the same on both runtimes, so it is a model/prompt item,
  not a native defect.
