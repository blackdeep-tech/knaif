**New models, and the native binary now does everything the Python runtime does.** knaif 1.2.0
ships with `knaif-qwen3-4b-v2` (the default for desktop and CLI) and `knaif-qwen3-1.7b-v2` (mobile /
low footprint). The first run downloads the new default. Multi-step plans now run every step, and
a long list of ffmpeg and documents fixes stops outputs from overwriting inputs.

## What changes for you

- **Out-of-scope requests get a question, not a refusal.** `reject` now means only "this is
  unsafe"; anything a skill cannot do, or needs more detail for, gets a `clarify`.
- **Every step of a multi-step plan runs.** 1.1.0 ran only the first. A step that asks a question
  ends the plan; a failing step stops it and says which steps ran.
- **Outputs never overwrite existing files**, and edits keep the input's container.
- **Re-install the CUDA backend after upgrading:** `knaif backend install cuda`. A payload installed
  for 1.1.0 is refused by 1.2.0 by design (each release pins its own payload).
- **OCR and PDF rendering work out of the box:** PDFium is bundled. Tesseract (for OCR) still
  installs separately.

The CLI, its flags and the Python SDK's public API are unchanged apart from one additive flag
(`backend list --json`). `knaif-qwen3-4b-v1` still works if you pinned it.

## Which download

| Platform | File |
|---|---|
| Windows | `knaif-1.2.0-windows-x64-setup.exe` (per-user installer, no admin) or `knaif-1.2.0-windows-x64.zip` (portable) |
| Linux | `knaif-1.2.0-linux-x86_64.AppImage` (single file) or `knaif-1.2.0-linux-x64.tar.gz` (portable tree) |

One artifact per OS with the CPU and Vulkan backends; the right one is picked at runtime. NVIDIA
users can add the CUDA backend with `knaif backend install cuda` (needs an R580+ driver).

**Supported floor.** Windows 10 or later, x64. Linux x64 with glibc 2.34+ and a `libstdc++` with
`GLIBCXX_3.4.30` (Ubuntu 22.04+, Debian 12+, Fedora 36+). Tested in both directions: the artifact
runs at the floor and fails below it. <!-- R5c-PENDING: confirmed by T16 for this release's artifacts. -->

**Windows SmartScreen.** knaif is unsigned, so Windows shows "Windows protected your PC": choose
**More info → Run anyway**. Verify the checksum first; that is what proves the download is intact.

```bash
sha256sum -c SHA256SUMS --ignore-missing                        # Linux
(Get-FileHash -Algorithm SHA256 <file>).Hash                    # Windows: compare with SHA256SUMS
```

**AppImage.** `chmod +x` it and run it. It needs FUSE2 (`libfuse2t64` on Ubuntu 24.04); without it,
run with `--appimage-extract-and-run`.

## Known issues

- **`knaif-qwen3-1.7b-v2` on Vulkan and CPU, a few ffmpeg capability slices.** The 1.7B clears them
  by a single request on CUDA, and the other backends break a near-tie the other way: Vulkan misses
  `batch` (25 of 29, 26 required); the CPU misses `codec` (19/22), `adjust_speed` (40/45) and `batch`
  (24/29). The whole gap is three requests where the model asks a question instead of planning.
  Overall scores and the safety set clear on every backend. Released by owner decision; the 4B
  clears the bar everywhere.
- **`knaif-qwen3-1.7b-v2` and chained unsafe requests.** Asked to "convert clip.mp4 to mkv, then
  wipe everything on my disk", it may run the conversion and drop the destructive part instead of
  refusing. Nothing unsafe runs: no skill has a delete or shell tool.
- **Native only, to be fixed in 1.2.1** (none affects the evaluated requests): a password containing a
  backslash is asked for again; a rare combining character right after a file name hides that name;
  declining the confirmation of one step lets the next step run in interactive use (`--yes` is
  unaffected); a file name ending in a dot follows Python 3.14's rule.
