**knaif on macOS, and an optional model daemon.** Same models as 1.2.0 (`knaif-qwen3-4b-v2`, the
default, and `knaif-qwen3-1.7b-v2`). macOS on Apple Silicon joins Windows and Linux, a daemon can
keep the model loaded between runs, and `knaif run` acts without asking unless a file would be
replaced.

## What changes for you

- **knaif runs on macOS** (Apple Silicon, macOS 12 or later), with Metal GPU inference. The signed
  and notarized `.pkg` installs it and offers the model and the supporting tools (through Homebrew,
  when it is installed); the `.zip` and `brew install blackdeep-tech/knaif/knaif` are the other ways
  in.
- **An optional model daemon.** `knaif daemon start` keeps the model loaded between runs (`status`,
  `stop`; it stops after 10 idle minutes, `--idle-minutes`), and `knaif run … --daemon` starts one if
  none is running. Runs use a running daemon by themselves and otherwise load the model as before.
  On an NVIDIA GPU a repeat run drops from about 2.6 s to 0.7 s; on a CPU it saves nothing
  measurable. Plans are identical either way.
- **`knaif run` acts without asking.** `--confirm` asks `Proceed? [Y/n]` before each step. Replacing
  a file that already exists **always asks** `Replace <file>? [y/N]` (Enter keeps it); `--yes` never
  approves that, `--overwrite` does, and without a terminal the step stops. Both runtimes behave the
  same.
- **The Windows installer no longer offers Ghostscript**, whose winget package was withdrawn;
  `knaif skills deps` points to Artifex's download page instead.
- **Setup and `knaif skills deps` say when Smart App Control blocks a supporting tool**, and setup
  shows those choices disabled with the reason instead of installing tools that cannot run.
- **`knaif models pull` survives a dropped connection**, picking up from what it already downloaded.
- **Re-install the CUDA backend after upgrading:** `knaif backend install cuda`. Each release pins
  its own payload, so 1.3.0 ignores the 1.2.1 one by design and says so.

Smaller changes: `knaif` and `knaif --help` show the version; an unsupported request no longer names
an internal argument; a `--dry-run` of `remove_pages` or `reorder_pages` checks the pages as the real
run does; removing every page of a PDF is refused in both runtimes; the Python runtime finds
supporting tools where the native one does. Full list: [CHANGELOG.md](https://github.com/blackdeep-tech/knaif/blob/main/CHANGELOG.md).

## Which download

| Platform | File |
|---|---|
| Windows | `knaif-1.3.0-windows-x64-setup.exe` (per-user installer, no admin) or `knaif-1.3.0-windows-x64.zip` (portable) |
| Linux | `knaif-1.3.0-linux-x86_64.AppImage` (single file) or `knaif-1.3.0-linux-x64.tar.gz` (portable tree) |
| macOS | `knaif-1.3.0-macos-arm64.pkg` (recommended) or `knaif-1.3.0-macos-arm64.zip` (portable), or `brew install blackdeep-tech/knaif/knaif` |

On Windows and Linux one artifact carries the CPU and Vulkan backends, picked at runtime; NVIDIA
users can add CUDA with `knaif backend install cuda` (R580+ driver). On a Mac knaif uses Metal.

**Supported floor.** Windows 10 or later, x64. Linux x64 with glibc 2.34+ and a `libstdc++` with
`GLIBCXX_3.4.30` (Ubuntu 22.04+, Debian 12+, Fedora 36+). macOS 12 or later on Apple Silicon; Intel
Macs are not supported.

**Windows.** The installer, `knaif.exe` and every bundled DLL are signed by **Blackdeep Technologies
Ltd** (`setup.exe` → Properties → Digital Signatures), so they install and run with Smart App Control
on. SmartScreen may still show "Windows protected your PC" for a new release: reputation builds up
per file over time, whatever the certificate. The prompt names the publisher; choose **More info →
Run anyway**. Verify the checksum first; that is what proves the download is intact.

**macOS.** The `.pkg` is signed, notarized and stapled, so it opens without a Gatekeeper warning even
offline; its options page offers the skills, the `PATH` link, the supporting tools through Homebrew
and the model download. The `.zip` is notarized too, but its first run needs the network for
Gatekeeper to look the ticket up. Supporting tools come from Homebrew; `knaif skills deps` prints the
exact `brew install` for each. On a macOS version Homebrew no longer builds packages for (macOS 12,
for example), Homebrew compiles ffmpeg from source, which can take hours; the `.pkg` downloads the
model before any tool, so the model never waits for it.

```bash
sha256sum -c SHA256SUMS --ignore-missing                        # Linux
shasum -a 256 -c SHA256SUMS --ignore-missing                    # macOS
(Get-FileHash -Algorithm SHA256 <file>).Hash                    # Windows: compare with SHA256SUMS
```

**AppImage.** `chmod +x` it and run it. It needs FUSE2 (`libfuse2t64` on Ubuntu 24.04); without it,
run with `--appimage-extract-and-run`.

## Known issues

- **`knaif-qwen3-1.7b-v2` on Vulkan, Metal and CPU, a few ffmpeg capability slices**, unchanged from
  1.2.0: the 1.7B clears them by a single request on CUDA, and other backends break a near-tie the
  other way. On Windows and Linux the whole gap is among the same three requests as in 1.2.0, where
  the model asks a question instead of planning. Overall scores and the safety gate clear on every
  backend; the 4B model clears the bar on every backend.
- **With Smart App Control on, some supporting tools are blocked on Windows.** knaif itself is signed
  and runs, but Windows blocks FFmpeg (so the `ffmpeg` skill cannot run) and the Tesseract and
  Ghostscript installers, which their makers do not validly sign. LibreOffice works. Smart App
  Control is on mainly on newer Windows 11 PCs; check under Windows Security → App & browser control.
- **On a Mac, the first run takes about 15 s longer** while Metal compiles its shaders; later runs do
  not pay it again.
- **The macOS `.pkg` keeps no receipt for the `PATH` link, the model or the tool choices**, so
  `pkgutil` does not list them. `/usr/local/knaif/uninstall.sh` still removes knaif and its link; the
  model stays in `~/.knaif`.
- Carried over from 1.2.0, unchanged: the `knaif-qwen3-1.7b-v2`'s handling of unsafe chained
  requests; "the second frame" read as the first; a file name ending in a dot following Python
  3.14's rule. See the 1.2.0 notes.
