**Bug fixes, a readable `knaif run`, and signed Windows binaries.** Same models, prompts and tool
contracts as 1.2.0: nothing changes in what knaif plans for a request. The Windows installer,
`knaif.exe`, every bundled DLL and the CUDA backend's `ggml-cuda.dll` are now signed by
**Blackdeep Technologies Ltd**, so the installer runs on PCs with Smart App Control on.

## What changes for you

- **Signed Windows binaries.** On a PC with Smart App Control on, Windows blocked earlier, unsigned
  installers outright ("An Application Control policy has blocked this file"). 1.2.1 installs, and
  upgrades an existing install in place. To check a download: `setup.exe` → Properties → Digital
  Signatures.
- **`knaif run` in a terminal draws the run as a tree:** the plan, each step with the command it
  runs, colors, timings and live ffmpeg progress. llama.cpp's own output appears only with
  `--verbose`. Piped or redirected output keeps the 1.2.0 lines, so scripts are unaffected.
- **Declining one step of a chain stops the plan**, and says which steps did not run. In 1.2.0 the
  next step ran anyway.
- **A failed ffmpeg command says why** in one sentence (permission denied, no such file, disk full,
  unknown encoder, …) instead of a raw exit code.
- **An encrypted PDF is reported as password-protected** instead of having 0 pages, and **a
  password containing a backslash is kept as typed** (on both runtimes `p\ss` could become `p/ss`).
- **Batch requests (`*.mp4`) run in the Python runtime** instead of failing with "not found".
- **Re-install the CUDA backend after upgrading:** `knaif backend install cuda`. Each release pins
  its own payload, so the 1.2.0 one is refused by 1.2.1 by design.

Smaller fixes: `reverse_video` shows its command before asking; a combining character right after a
file name no longer hides it; a missing `core_tools.yaml` is a startup error naming the file; with
no GPU the CUDA tip no longer says Vulkan "already works here"; run from inside a knaif source
checkout of another version, the CUDA backend is no longer reported as stale.

The CLI, its flags and the Python SDK's public API are unchanged.

## Quality

1.2.1 changes no model, prompt or tool contract, so it was checked against 1.2.0's full measurement
rather than re-measured. The packaged 1.2.1 binary ran a sample of 47 ffmpeg and 31 documents
requests (20 + 10 at random, plus every multi-step request, every `reverse_video` phrasing and every
request with a password), one fresh process per request, on Windows and on Linux with CUDA,
executing for real and graded on the files produced. **Every request gave the same plan, outcome and
score as in 1.2.0**, so the [1.2.0 results](https://github.com/blackdeep-tech/knaif/releases/tag/v1.2.0)
stand for this release. On the same sample (43 ffmpeg and 31 documents requests that plan), the
Python and native runtimes rendered the same commands as they did for 1.2.0.

**Coverage:** Windows x64 and Linux x64. The release was also installed in a clean Windows Sandbox
with Smart App Control enforcing: fresh install, and an upgrade over 1.2.0. macOS is not part of
this release.

## Which download

| Platform | File |
|---|---|
| Windows | `knaif-1.2.1-windows-x64-setup.exe` (per-user installer, no admin) or `knaif-1.2.1-windows-x64.zip` (portable) |
| Linux | `knaif-1.2.1-linux-x86_64.AppImage` (single file) or `knaif-1.2.1-linux-x64.tar.gz` (portable tree) |

One artifact per OS with the CPU and Vulkan backends; the right one is picked at runtime. NVIDIA
users can add the CUDA backend with `knaif backend install cuda` (needs an R580+ driver).

**Supported floor.** Windows 10 or later, x64. Linux x64 with glibc 2.34+ and a `libstdc++` with
`GLIBCXX_3.4.30` (Ubuntu 22.04+, Debian 12+, Fedora 36+).

**Windows SmartScreen.** SmartScreen may still show "Windows protected your PC" for a new release:
reputation builds up per file over time, whatever the certificate. The prompt now names the
publisher; choose **More info → Run anyway**. Verify the checksum first; that is what proves the
download is intact.

```bash
sha256sum -c SHA256SUMS --ignore-missing                        # Linux
(Get-FileHash -Algorithm SHA256 <file>).Hash                    # Windows: compare with SHA256SUMS
```

**AppImage.** `chmod +x` it and run it. It needs FUSE2 (`libfuse2t64` on Ubuntu 24.04); without it,
run with `--appimage-extract-and-run`.

## Known issues

- **On a PC with Smart App Control on, some supporting tools are blocked.** knaif itself is signed
  and runs, but Windows blocks unsigned third-party programs there, even online:
  - **FFmpeg** (the Gyan build winget installs) is blocked, so the `ffmpeg` skill cannot run;
  - **Tesseract** and **Ghostscript**: their installers are blocked, so OCR and the strongest PDF
    compression are unavailable (the `documents` skill otherwise works);
  - **LibreOffice** installs and works.

  Smart App Control is on mainly on newer Windows 11 PCs; where it is off or in evaluation mode,
  nothing changes. Check under Windows Security → App & browser control.
- **The Ghostscript winget package no longer exists:** `knaif skills deps` and the installer's
  optional task suggest `winget install ArtifexSoftware.GhostScript`, which fails. Install
  Ghostscript from https://ghostscript.com/releases/gsdnld.html instead.
- **An existing output file is replaced without asking:** ffmpeg commands overwrite their output,
  and documents does the same for an output name you give it. Names knaif picks for documents get
  a `-1` suffix instead. The terminal view now warns before such a step.
- Carried over from 1.2.0, unchanged: the `knaif-qwen3-1.7b-v2` capability slices on Vulkan and CPU
  and its handling of unsafe chained requests; "the second frame" read as the first; a file name
  ending in a dot following Python 3.14's rule. See the 1.2.0 notes.
