# evals — run history

Per-skill scoreboard JSONs carry **no embedded metadata** (no date, git SHA, backend, or
corpus hash — backend is only in the filename, mode is the `verifier` field). This index is
the source of truth for *what each run was against*. **Add a row here whenever you save a run.**

**Exception — all-skills sweeps.** `run --all-skills` also writes a `matrix.json` carrying a
`meta` block (`label`, `date`, `git_sha`, `git_branch`, `backends`) plus a per-skill ×
backend metric grid. That makes a single model build self-describing, so a skill's history
across builds is reconstructable from the folders alone:

```
uv run -m knaif.evalsuite trend --skill documents          # metric history across builds
uv run -m knaif.evalsuite trend --skill ffmpeg --last 5    # last 5 model builds only
```

## Layout

```
evals/
  INDEX.md          <- this file (run history)
  baselines/        <- reference runs we compare against (one folder per locked baseline)
  runs/             <- new working runs (one dated folder per run)
  _archive/         <- superseded / non-comparable historical runs (kept, not deleted)
```

## Naming convention (for `runs/` and `baselines/`)

```
<YYYY-MM-DD>_<label>_<verifier>/
    <skill>_<backend>_<verifier>.json     # one per skill × backend
    matrix.json / matrix.md               # all-skills sweeps only (build meta + grid)
```

- `label` — short slug describing the code state, e.g. `pre-geometry`, `post-geometry`, `crop-fix`.
  For all-skills sweeps it defaults to the run-folder name; override with `run --all-skills --label`.
- `verifier` — `cheap` (routing only, no execution) | `success` (real execution + success_criteria) | `output_diff`.
- `skill` (`ffmpeg`, `documents`, …) and `backend` (`qwen3-4b`, `gemma3-4b`, …) stay in the
  filename, as the suite writes it. (Single-skill `run --skill X` writes only the per-skill
  file; `run --all-skills` adds the `matrix.*` summary.)
